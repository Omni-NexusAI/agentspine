5 · An unavailable mode says why, and what would make it available

There are three ways a mode can be unavailable, and each looks different: not in this version (can’t be chosen), not with this model (can be chosen; a check failed), and needs setup (can be chosen; something is missing, page 4). In all three, Convo refuses to start with the same words the card shows.

What to look at

  • Three badges, three border styles: dotted “Not in this version”, dashed “Not with this model”, dashed warning “Needs setup (n)”. Words and icon carry the meaning; the border is a second cue.
  • Every unavailable state answers two questions: what failed (with the check and its date) and what would make it available (an action, not advice).
  • The start refusal repeats the card’s words and ends with “Nothing was sent.” There is no automatic switch to another mode or model; the chip names the mode that was asked for.
  • Refusals come back from convo.start as data (ok: false, refused: true, message), so the host never masks them as “Internal server error”.
