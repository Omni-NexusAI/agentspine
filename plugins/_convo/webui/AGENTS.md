# Convo interfaces

- The native sidebar and expanded Studio are separate interfaces. Navigation must not stop, recreate, or retarget an active voice session.
- Studio availability probes use native same-origin `fetch` on `/convo-studio/` after `studio_open` establishes the session. Host `fetchApi` adds `/api/` and must not be used for this root WSGI route.
- Distinguish the rendered Studio interface from managed audio/profile readiness. Never render raw backend tracebacks; preserve unavailable saved voices visibly and disable their selection action until inventory verifies them.
- Version the Studio modal and its module reference together when deploying interface changes; verify from a fresh page so a prior module instance cannot retain watchers.
- `setup-store.js` and `settings-controls.html` own one shared draft and revision-aware save path. Native plugin settings adapt only their local modal context, never the host settings prototype.
- Discovery and connection tests require an explicit user action against configured endpoints. Preserve unavailable saved choices; never infer audio or duplex capabilities from a model list.
- Dynamic option lists explicitly bind selected values; a saved unavailable model/voice must not visually revert to the empty placeholder during initial rendering. Development mode displays voice-idle state while keeping dictation/settings available.
- API keys remain transient, write-only inputs; empty input preserves a saved key, explicit clear schedules removal. Never persist credentials in browser storage.
- Keep visual metering observational: one existing capture, no new microphone stream, no admission changes. Meter failures must not block audio cleanup.
- Experimental PCM playback uses the existing AudioContext/output gain and session/epoch/turn-bound begin/chunk/end events. Require PCM16 mono metadata, consecutive zero-based chunk sequence, bounded scheduled audio, explicit end and all sources finished before acknowledging completion. Interruption/error discards pending sources without completion; raw PCM never enters the buffered WAV decoder. Transport support is not live listening acceptance.
- Candidate policy probes reuse the same captured PCM as completed turns. A VAD
  onset must not cancel playback. Only the server's epoch-bound semantic admission
  clears queued audio; pending/unclear/degraded policy ducks existing output.
  Preserve final-turn identity across the admission epoch transition. A duck lasts
  only while a decision is pending: a completed turn's terminal decision (even
  withhold/degraded) releases it unless a newer utterance is open, a new reply never
  starts ducked, and a safety timer releases it once the user has stopped and nothing
  is waiting. `busy`/`stale` answers are ordinary, not an outage: a probe is replaced,
  a completed turn is re-sent for a few seconds, a stale one is dropped.
- Anything that writes to host-owned elements must converge with the host's own observers. The host's tooltip observer moves `title` into `data-bs-original-title` and removes `title`, so the orb writes its tooltip text to `data-bs-original-title` when that system is present and never watches or re-writes `title` (doing so froze the page in a mutation ping-pong). `tests/orb-ui.test.mjs` models both sides; confirm any change to host-element attributes on the isolated live host, where a freeze shows up immediately.
- Echo guard (`echo-guard.js`, `audio-worklet-guard.js`, setting `echo_guard`): capture input 0 is the microphone, input 1 the post-duck `outputGain` (the exact playback reference); `nativeAec` comes from the live track's `getSettings()`. The guard is classification-only: the NLMS predictor's residual is never sent, released frames are the original capture samples, withheld time is reported as `dropped` and fed to `SpeechBoundary` as silence (so a turn still ends), and `strict` withholds everything during playback. The guard's measured noise floor (clamped .0015-.03, fixed .02 until calibrated) is the boundary's voiced threshold (`push(chunk, floor)`); `off` is a different worklet file and capture path, unchanged. A recreated session (retarget) restores the learned echo path from `echoSnapshot()`. Admission needs `MIN_VOICED_SECONDS` (.45) of voiced audio, the same 450 ms the guard confirms during playback, so a shorter one-word interruption is not detected; change it only with replay measurements. `PRE_ROLL_SECONDS` (default 0 = off) keeps audio before the first voiced block.
- Ducking is `DuckController` behind `setPolicyHold(held, immediate)`: attack 40 ms, hold at least 350 ms, release only 850 ms after the last request to duck (longer than the 750 ms probe cadence, so it does not pump), release ramp 250 ms, and a 12 s cap so it can never stick. A decision that already ended (admission, a new reply) passes `immediate`.
- `SpeechBoundary` cuts a turn on the exact sample of the server's maximum length and
  carries the rest of that block into the next utterance, so an uploaded turn never
  exceeds what the server accepts.
- The speech gate constants (`policy_gate.*`) are plain probability inputs in Advanced ("Speech gate"). They belong to one decision model and one kind of speech: the hint says so, tells the user where to measure again (`tests/calibrate_gate.py`), and says that work with side effects always needs an explicit request at 0.9 or more. The server refuses an inconsistent set (ambient below active, a waving-away floor under 0.5) and the editor shows its message. Whether the gate is calibrated or unsupported for the selected classifier is a readiness row (`speech_gate`), not something the browser infers.
- "Answer length" and "Spoken task updates" (Conversation section) are plain enum selects on the shared `convoSetup` draft (`response_detail`, `spoken_updates`), so the plugin Config and the canvas gear modal edit the same value; `tests/test_settings_coverage.py` keeps every stored setting bound to a control. The hint states the boundaries (next response versus session start) and that errors, permissions and decisions are always spoken. Nothing in the interface may imply streaming input.
- Use host theme tokens and button conventions. The sidebar explicitly owns its column layout; do not rely on inherited panel flex direction.
- Delayed transcripts replace the matching visible accepted-turn text without mutating the durable event journal. Generated drafts and playback-start events are not delivered speech.
- The canvas panel is history-first: a compact header (status chip, Voice Studio, settings gear), the chat target, the conversation controls, then the transcript, which is the only scroller. Settings never render in the panel; the gear opens `settings-modal.html` through `ensureModalOpen` over the same `convoSetup` draft the plugin Config uses, and closing a dirty modal asks first. The "jump to latest" button stays outside the scroller (inside it, showing the button lengthens the content and un-pins the reader). Journal bookkeeping (`assistant.generated`, playback starts, compaction, job lifecycle noise) is hidden outside developer mode; only real journal facts are described, never inferred markers.
- The host moves a modal's `[data-modal-footer]` out of the body: bind `:hidden`, not `x-show`, inside it. The host provides no focus trap; the modal wraps Tab itself. Use timers, not `requestAnimationFrame`, for settle logic (frames pause in a hidden pane).
- The composer orb is Convo's visual state layered on the host microphone button (`orb.js` + `page-head/zz-convo-orb.html`) and is released exactly when Convo is off. State comes from `orbView`; every state has its own glyph, a spoken label and `aria-pressed` truth, so nothing relies on colour; hover only brightens. The host rewrites the label and pressed state on its own events, so the orb watches and reasserts them. One capture and one set of existing meters feed it; the orb adds no stream, model or admission change.
- The orb's press gesture is `dictation.js`: a pure state machine (`createGesture`, injected timers, no DOM) plus a thin DOM adapter (`bindOrbGesture`). It only decides (`PRE_OPEN_MS` opens the silent buffer, `LATCH_MS` adopts it as latched dictation, `PUSH_TO_TALK_MS` makes it push-to-talk; `data-convo-capture` is the quiet mark while it buffers); the store acts on its effects (`tap`, `arm`, `push-to-talk`, `latch`, `finish`, `cancel`, `abort`). The click that follows a handled release is swallowed (`consumeClick`), a click with no press (assistive technology) acts as a tap, and Space/Enter on the focused orb are the same gesture. Dictation states are `dictating-latched` (pen glyph, closed second ring) and `dictating-ptt` (own glyph, heavy ring, pressed-in core); a press heading for the latch time charges a ring (`data-convo-press`, duration kept equal to `LATCH_MS` by test). Transitions are also said through the polite live region (`announce`) and the `note`; `dictation-ptt` is a cue. The held recorder (`startManual`, `setManual`, `finishConvoDictation`, `discardConvoDictation` in `enhanced-stt-recorder.js`) is the host recorder itself: no second stream, pure silence is not transcribed, a cancelled transcript is never delivered.
- Sound cues are optional hooks: transitions emit `convo:cue` (activate, deactivate, dictation-start, dictation-ptt, dictation-end, error); `sound-cues.js` plays a clip only when `sounds/manifest.json` names one, creates no `AudioContext`, and treats every failure as silence.
- Timing marks (`markTurn`, `timingReport()`) are content-free `performance.now()` measurements for measurement runs only; they never gate capture, playback or admission.
- Pure modules (`view-helpers.js`, `orb.js`) have no imports so the store, the markup and node tests share one definition; older VM fixtures that restrict import specifiers map them to the real files.
- Run `node --experimental-vm-modules --test plugins/_convo/tests/ui.test.mjs plugins/_convo/tests/setup-ui.test.mjs plugins/_convo/tests/dictation.test.mjs plugins/_convo/tests/dictation-store.test.mjs` and `node --test plugins/_convo/tests/audio.test.mjs`. Rendered host and listening acceptance remain separate checks.
- `settings-controls.html` is a shell (tabs, `settings-banner.html`, the Conversation section, echo protection, the Developer row, the footer) composing one x-component per card: `conversation-model-field.html`, `classifier-model-field.html`, `speech-output-field.html` + `speech-voice-field.html`, `dictation-field.html`, `tuning-controls.html` (Advanced). `.convo-settings x-component{display:contents}` keeps each card laid out as if inline; a card fixes its role with `x-data="{ role: '...' }"` and imports `setup-store.js` itself. Nesting works in the plugin Config modal because the host imports every x-component added under `<body>` (verbatim v2.11 fixtures `tests/fixtures/host-components.js`, `host-plugin-settings*.{html,js}`). Markup checks read every file reachable from `config.html` and `settings-modal.html` (`tests/settings-markup.mjs`, `test_settings_coverage.py`); a setting counts only through a real binding (x-model, :value, :checked, @change, @input), and a card whose control is still to come declares `<!-- convo-settings-pending: path, ... | reason -->` in its own file.
- `setup-store.js` keeps state, getters and the shared role helpers; each card's methods live in its own methods-only mixin (`conversation-setup.js`, `classifier-setup.js`, `speech-setup.js`, `dictation-setup.js`) joined by `compose`, which refuses a getter, a value or a name defined twice. Card view state goes in `ui.<card>`. `patch(changes)` sets and saves some paths now and `adopt(result)` merges the answer three ways (other unsaved edits and pending keys survive, a path changed elsewhere becomes a conflict); a patch and a save never overlap, and the editor's own patch is never flagged as "changed elsewhere". The speech tables and switching live in `speech-catalog.js` (re-exported by `defaults.js`). The Developer row binds `developer_mode` and `ai_link_development_mode`; "Open diagnostics" calls `$store.convoDiagnostics?.open()` and shows only when that store exists.
- `convo-store.js` diagnostics taps are observational: `taps.echo` receives echo-guard metrics from every AudioSession (a throwing or absent tap is ignored) and `audioSnapshot()` reports duck, toggles, playing, queue and PCM counts, never audio.
- Model cards are one factory: `model-role-setup.js` `modelRoleSetup(role, spec)` returns `<role><Name>` methods (provider options, provider info and address, `SetProvider`, the provider-change hook, autosave with ONE timer and flush per role, conflicts, search and grouping, keys, readiness rows, remote advice; `Probe`/`CopyKey` only when the spec names their action). `conversation-setup.js` and `classifier-setup.js` are a spec plus card-specific methods. Agent Zero's `modelConfig` store (imported once, shared, kept in a module variable) is read at the moment of use: `chatProviders`, `chatProviderDetails`, `searchModels`, `groupResults` and, when present, `onProviderChanged` (else Provider Profiles' `onProviderProfileChanged`), which gets an adapter slot (`name` = the role's model, `ctx_length` = the card's context path, provider read-only, other fields dropped; what it changed is marked edited). No card keeps a provider list: catalogs hold Convo's verdicts only. A provider Convo has no entry for is selectable when Agent Zero's details give LiteLLM route `openai`/`hosted_vllm` plus an API base ("audio not verified" / "not verified"; base prefilled from Agent Zero, Convo's own key, host search); a provider with a Convo reason stays disabled even then.
- `connection-rules.js` holds what every connection card shares: `isLocalHost` (the browser copy of `convo_contract.local_host`: this machine, LAN and Tailscale need no consent), `credentialReferenceProblem` and `NETWORK_HINT`; `model-role-setup.js` and `speech-catalog.js` import it, and `connection-rules.test.mjs` holds it to the server's table. A provider whose own address is on this machine (llama.cpp, vLLM, a local decision server: `<role>LocalServer()`) shows API base URL as a main field with `<role>ServerHint()`, never as an Advanced override, so pointing it at another computer is one edit. Credential-reference fields check as you type (`<role>ReferenceProblem`, `speechReferenceProblem`), hold the autosave with the reason and offer Clear (`<role>ClearReference`, `speechClearReference`).
- The Classifier card (`classifier-model-field.html` + `classifier-setup.js`, the factory on `roles.classifier.*`): Provider (ONE select, optgroups Local servers / Cloud / Other providers / Other from the server's `classifier_catalog` merged with Agent Zero's providers; disabled ones with their reason), Model name, API key, Context window (1024–1000000), Accepts audio input, Allow remote processing (only for an address off this machine/network or a consent already given), Advanced (API base URL, Key source, Classifier type Auto/Decision/Chat limited to the provider's `kinds`, credential reference, Check server → `classifier_check` with what is shown, refused inline before sending when the address would be, answered inline, stale answers dropped, "Use it as a … model" when it found the other kind). Underneath, "Use System One's decider" is `decider.source === 'system_one'`: on, the same fields show `decider_reference` read-only (provider, model, endpoint host, context window) with the verdict (words + `aria-hidden` icon; none sent = never usable) and a link to Agent settings → Models (`settings-store` `open('agent')`, never awaited: it resolves on close); off writes the source saved before (or `convo`). The card never writes derived fields (`decider.url/model`, `system_one`, `roles.classifier.url` for a provider): the server's normalizer does. A separate decider saved before the card (`decider.source` `convo`/`''`, `system_one` on with `d1_llama_cpp`, provider `''`) is a VIEW (`classifierMigration`): llama.cpp, decision, `decider.url || :9931` + `/v1`; the four migrated fields bind `:value="classifierMigration()?.x ?? config…x"` and write through `classifierSet`/`classifierSetProvider`/`classifierSetKind`, which adopt the view first, so showing it never dirties the draft. The developer backend picker stays in Tune (`decisionOptions`).
- Continuous drafting changes only words: the orb keeps the `dictating-latched` id, glyph and cues and reads "Dictating into the composer — keeps listening until you send or stop." (`orbView` `continuous`); its ends use `dictationEndNote` ("Dictation finished · N phrases added; nothing was sent." plus send, cancel and off variants). The Whisper modal's third option comes from `extensions/webui/modal_content_loaded/_30_convo_whisper_mode.js`: only the plugin settings modal while it shows Whisper's config, one observer released on close or for another plugin, idempotent, nothing offered when `stt_status` cannot answer; the stored choice is shown by setting the modal's settings and its `settingsSnapshotJson` alike, so the host's `hasUnsavedChanges` stays false; the legacy Whisper Save forwards it unchanged. The dictation card's select (`messageMode(flag, hostMode)` shows what really applies) calls `applyMessageMode`: `stt_config` at once, the answer merged into the host Whisper store, `setup_read` adopted while `busy` (no stale banner, other unsaved edits kept), and the select re-synced on failure.
- Diagnostics panel (`diagnostics.html`): one time axis per turn (server seconds mapped to `performance.now()` through the poll round trip; steps that cross the two clocks show ± half the tightest round trip), bounded to 20 turns and 2000 marks, rendered only while visible. Every bar, track and meter is `aria-hidden` with its words beside it, failures carry an icon and words, the waterfall is an `<ol>`; no live region and no `title`; sections are buttons with `aria-expanded`/`aria-controls`; colours are tokens checked at 4.5:1 for text and 3:1 for bars in both host themes (`.light-mode`); reduced motion removes transitions and slows the meters (written straight to the DOM, 4 Hz) to 1 Hz. The pop-out (`floating-window.js`) is a non-modal labelled dialog on `<body>` at z-index 4000 (above the canvas, below host modals); its geometry is clamped on restore and on viewport changes and saved only after a user drag, resize or keyboard move while visible with a non-zero size (storage errors ignored); Escape inside it docks it with propagation stopped (a modal behind stays open) and focus returns to Pop out; below 640 px it is a bottom sheet. Its frame styles live in the canvas wrapper, which loads with the canvas. Tune is `tuning-controls.html` (the former Advanced tunables and the registered decision-backend picker; the classifier itself is on the Classifier card) composed with `settings-banner.html`, an echo-protection mirror and its own Save over the shared `convoSetup` draft.
- The three Connections cards read alike: each is `<fieldset class="convo-card convo-model-card …">` with the legend title, a `.convo-model-note` description, `.convo-model-fields`, host `.field`/`.field-title`/`.field-description` (hints included), host `.toggle` switches and the `.advanced-toggle` section. Their field, note, toggle and advanced styles are the conversation card's `.convo-model-card` rules (the shell composes it first); no other card restyles the host field classes or sets its own colours (host tokens only; `settings-split.test.mjs` checks it). `speech-voice-field.html` (Voice & Audio) uses the same classes.
- The speech output card is a provider editor laid out like Agent Zero's model settings: grouped provider select, audio.cpp connection, server URL, API key (OpenAI: Agent Zero's `openai` key or a Convo-only key), consent, Find models & voices / Test connection with what each route answered, model and voice, voice delivery, advanced. `speechControls()` names the controls (vocabulary `SPEECH_CONTROLS`); the markup only asks `show('tts', name)`. The provider and connection selects go through `setSpeechProvider`/`setSpeechConnection` (stash and restore in `speech-catalog.js`) and are re-synced to what is in effect; model, voice and the declaration go through `speechUpdate` so the draft is normalized as the server would store it. Model and voice are a typed id plus a keyboard listbox (`role=combobox`, `x-id`-scoped ids; arrows, Enter, Escape closes only the list, Tab leaves) over what discovery listed, or fixed selects for OpenAI; nothing is fetched until a click. Host speech registered only in the browser (`ttsService`) is listed disabled ("browser-only; Convo speaks from the server"). Parse addresses without `URL` (not every context and no test VM has it). Voice & Audio shows Kokoro's summary or a provider/model/voice summary, managed tuning, the server's tuning selection and the PCM toggle.
- The conversation card (`conversation-model-field.html`, `conversation-setup.js`) has Agent Zero's model-field structure and classes (`.field`, `.field-label`, `.field-control`, `.toggle`, `.model-search-*`, `.advanced-*`, `.masked-text-input`) and its own copies of the search and advanced styles, scoped to `.convo-model-card` (the Convo modal does not load the host's model-field CSS); a container query stacks fields in a narrow card. The same card is Convo → Connections (saved with Save; conflicts in the banner) and the preset editor's model type (`model-type-mount.js` wraps it in `x-data="{ convoAutosave: true }"`: every control reports its path through `conversationEdited(path, autosave)`, and only that copy shows the autosave status line and inline conflicts). `CONVERSATION_CATALOG` mirrors `convo_model_catalog.py` (contract test) and holds Convo's audio verdicts only. Agent Zero's providers, details, model search, grouping and key store come from its `modelConfig` store at the moment of use (the factory above); the store, the role's timer and the autosave in flight stay in module variables, never in reactive state. Other and the endpoint-only setup search through Convo's own discovery, so no Agent Zero key goes to a server you run. Model name is a keyboard combobox (arrows, Enter; Escape closes only the list); no control writes `title`. Advice that mirrors the server (`conversationUrl`, `addressProblem`) only holds an autosave; the server still decides.
- A card can render before the `convoSetup` store exists; Alpine evaluates each binding once then and never re-runs one that threw, so a button stays disabled or a result hidden for good (found live). Read card view state only as `$store.convoSetup?.ui?.<card>?.…`, and make a `:disabled` that reads it strictly boolean (`=== true` or a leading `!`); `tests/binding-guard.test.mjs` enforces it.
- Every model card shows its Test (the classifier's Check server) beside its address, not in Advanced. Under the answer it shows the connection extras from the store core:
  - `thisComputerText`;
  - `keyMoveOffer` / `keyMove`;
  - `connectionSuggestion` with `<role>UseAddress`;
  - `<role>CloseMatch`;
  - `certificateNote` / `certificateForget`;
  - `certificateChanged` / `certificateAccept`.

  Bindings inside `x-if` stay null-safe, because the binding test evaluates them in every state. Only the newest discovery answer is shown, and only while the card's address, provider and key source are unchanged; typing a model name keeps it.
