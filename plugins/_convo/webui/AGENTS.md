# Convo interfaces

- The native sidebar and expanded Studio are separate interfaces. Navigation must not stop, recreate, or retarget an active voice session. The one exception is not a retarget either: in a conversation across chats, selecting a chat changes only the default place for work (`convo.work`), never the session, its audio or its history.
- One conversation across chats (`GLOBAL_SCOPE` = `'convo:global'` in `view-helpers.js`, the browser copy of the server's; the store's `across` is `target === GLOBAL_SCOPE`): the server decides which conversation a start is and says so in `session.target` (the setting `conversation_scope` "global", or no chat selected); a session without a target is the chat's own. `start` sends the selected chat's id or `''` and never refuses for want of a chat. While voice is off the panel shows `idleTarget()`: that conversation when the setting is "global", else the selected chat's own. Across chats the status poll's look at the selected chat (`noteWork`) sends `convo.work {chat}` after `workDebounceMs` (300), never while starting or re-attaching, once per selection (`workAsked`; a `stale`/`busy` answer is tried again, any other refusal is said once); the answer's `work`/`name` are what the chat line shows: "Working in: <name>", "Working in: an untitled chat" or "No chat selected" (`targetPrefix` + `targetLabel`). No "Use selected chat" there (`canRetarget` is false, `retarget()` only sends `work`). History, earlier pages and memory use `target`, so they are that conversation's. Completion notices are claimed for every job its history returned, whichever chat it ran in (`job.target` is the real chat; a chat's own conversation still claims only its own chat's). The task list names a job's chat (`jobChat`: the `job.queued` event's `chat`, else the host chat list's title, else nothing). The two settings (`conversation_scope`, `task_chat`) are plain selects near the top of Settings -> Conversation on the shared draft. A chat's own conversation is unchanged. Tests: `across-chats.test.mjs`.
- The plan (planning mode): `plan` comes with every history answer (never from a page's own memory), `takePlan` is the only place that takes
  one in; an answer older than one already taken in (a slow poll) is left alone (`planMark`). The field shows the plan, or the user's unsaved edit (`planDirty`, made on revision `planBase`, which said `planFrom`), which is never
  replaced: a save that Convo wrote under meanwhile asks which one to keep (`planClash`: Save mine / Use the new one); what is typed while one
  is being saved is the next edit; when another plan or chat takes its place it is saved to its own plan (`keepEdit`), or kept to be copied
  (`planLost`: a list, one entry per lost edit); one answer without a plan changes nothing. Ending, going on, opening an earlier plan (`planEarlier`) or handing over saves an
  edit first and stops when that fails; so does discarding, which keeps what was typed when it fails. `putBack(version)` fetches one of the texts that stood there before (`planVersions`) and shows it as an edit. A question about a plan
  that is done with goes (`planId`). The Plan button begins a new plan (`fresh`); "Go on planning" goes on with the one kept last. The hotkey looks first when nobody was looking (`look`), and its failure is announced. The card opens by itself when planning begins and stays as the user leaves it. A textarea, so the transcript
  stays the panel's only scroller; no `x-model`. A task that waits says so (`jobState`). Planning switched on drops the open question's card.
  The hotkey row stores `planning_hotkey`, beside the table. Tests: `plan-panel.test.mjs`.
- A change to a task (Steer): one field at a time under its task (`steerOpen`, `steerText`), never a prompt window, and no `x-model` (the panel holds no editable settings). The button and its title say what it does: `steeringOn` (the history answer's `steering`) = it goes in at the next step, else Interrupt; a queued task is added to either way. A failed change keeps its words. `job.change` (the newest change's state) and the journal's `job.steer*` rows read as words (`view-helpers.js`); `job.steered` refreshes the history. Tests: `steer-panel.test.mjs`.
- Studio availability probes use native same-origin `fetch` on `/convo-studio/` after `studio_open` establishes the session. Host `fetchApi` adds `/api/` and must not be used for this root WSGI route.
- Distinguish the rendered Studio interface from managed audio/profile readiness. Never render raw backend tracebacks; preserve unavailable saved voices visibly and disable their selection action until inventory verifies them.
- Version the Studio modal and its module reference together when deploying interface changes; verify from a fresh page so a prior module instance cannot retain watchers.
- `setup-store.js` and `settings-controls.html` own one shared draft and revision-aware save path. Native plugin settings adapt only their local modal context, never the host settings prototype.
- Discovery and connection tests require an explicit user action against configured endpoints. Preserve unavailable saved choices; never infer audio or duplex capabilities from a model list.
- Dynamic option lists explicitly bind selected values; a saved unavailable model/voice must not visually revert to the empty placeholder during initial rendering. Development mode displays voice-idle state while keeping dictation/settings available.
- API keys remain transient, write-only inputs; empty input preserves a saved key, explicit clear schedules removal. Never persist credentials in browser storage.
- Keep visual metering observational: one existing capture, no new microphone stream, no admission changes. Meter failures must not block audio cleanup.
- Experimental PCM playback uses the existing AudioContext/output gain and session/epoch/turn-bound begin/chunk/end events. Require PCM16 mono metadata, consecutive zero-based chunk sequence, bounded scheduled audio, explicit end and all sources finished before acknowledging completion. Interruption/error discards pending sources without completion; raw PCM never enters the buffered WAV decoder. Transport support is not live listening acceptance.
- Candidate policy probes reuse the same captured PCM as completed turns. A VAD
  onset must not cancel playback. Only the server's epoch-bound semantic admission
  clears queued audio; pending/unclear/degraded policy ducks existing output.
  Preserve final-turn identity across the admission epoch transition. A duck lasts
  only while a decision is pending: a completed turn's terminal decision (even
  withhold/degraded) releases it unless a newer utterance is open, a new reply never
  starts ducked, and a safety timer releases it once the user has stopped and nothing
  is waiting. `busy`/`stale` answers are ordinary, not an outage: a probe is replaced,
  a completed turn is re-sent for a few seconds, a stale one is dropped.
- Anything that writes to host-owned elements must converge with the host's own observers. The host's tooltip observer moves `title` into `data-bs-original-title` and removes `title`, so the orb writes its tooltip text to `data-bs-original-title` when that system is present and never watches or re-writes `title` (doing so froze the page in a mutation ping-pong). `tests/orb-ui.test.mjs` models both sides; confirm any change to host-element attributes on the isolated live host, where a freeze shows up immediately.
- Echo guard (`echo-guard.js`, `audio-worklet-guard.js`, setting `echo_guard`): capture input 0 is the microphone, input 1 the post-duck `outputGain` (the exact playback reference); `nativeAec` comes from the live track's `getSettings()`. The guard is classification-only: the NLMS predictor's residual is never sent, released frames are the original capture samples, withheld time is reported as `dropped` and fed to `SpeechBoundary` as silence (so a turn still ends), and `strict` withholds everything during playback. Every candidate frame must be voice-like (voicing below); echo evidence counts only at correlation >= .6 at a stable lag (the delay estimate moves only then); `coupled` falls back to `uncoupled` after 240 ms of clean playback; with no echo evidence a voiced frame is independent speech (450 ms releases the onset; a quiet pause between words may last `QUIET_GAP_MS` 500); a modeled-human frame needs the raw mic not to match the playback; double-talk state clears when playback ends. Once double talk is confirmed, a frame that is not echo is kept only within `KEEP_NEAR_VOICE_MS` (250) of the user's voiced frames, before or after (a frame that may precede voice waits at most that long in a short queue); kept frames are original audio and carry the reply too. Echo and anything farther from the voice, and all withheld time until playback ends, become floor-level comfort noise (`COMFORT_MIN_RMS` .0002 to `HUMAN_FLOOR_MIN_RMS`, deterministic, `COMFORT_FADE_MS` 5 crossfades) instead of digital zeros: flagged `comfort` per frame, never voiced, past the gate. Results carry `released` (original frames, for accounting) and the ordered `frames`/`voiced`/`levels`/`comfort` to send; the worklet posts those plus `playback`. Released frames carry `voiced`/`levels`, which the boundary counts instead of RMS. The guard's measured noise floor (clamped .0015-.03, fixed .02 until calibrated) remains the legacy voiced threshold for blocks without a verdict (`push(chunk, floor)`); `off` is a different worklet file and capture path, unchanged. A recreated session (retarget) restores the learned echo path from `echoSnapshot()`. Admission needs `MIN_VOICED_SECONDS` (.45) of voiced audio, the same 450 ms the guard confirms during playback, so a shorter one-word interruption is not detected; change it only with replay measurements. `PRE_ROLL_SECONDS` (.4) keeps audio before the first voiced block: the smallest value that kept every first word the corpus replay can keep (537 clips, off and adaptive paths, measured 2026-11-17; re-measure live). It is never speech (admission, `voiced_s`, the safety yield unchanged), is reported as `pre_roll_s` on probes and finals (the server subtracts it from "short command" and the joining gap), and the ring holds the ungated audio: the pre-roll and the opening block are sent ungated with a `PRE_ROLL_FADE_MS` (8) fade-in (`push(chunk, floor, verdict, raw)`). With echo protection Off there is no pre-roll while the assistant plays or within its echo tail (`allowPreRoll` = `!playbackNow()`); with the guard, withheld time is already silence or comfort noise.
- Upload (`Resampler`, `TurnEncoder`, `wavBase64`): 16 kHz mono PCM16 through a windowed-sinc low-pass (Blackman, `RESAMPLE_ZEROS` 24, cut-off `RESAMPLE_CUTOFF_HZ` 7000; > 50 dB down above 8 kHz, edges hold the first/last sample, linear below 16 kHz, same frame count rule as before). `TurnEncoder` resamples and packs each block once per utterance; a probe adds a provisional end without consuming it. The voicing analysis (`Decimator`, the guard's decimation) is unchanged. The classifier, Whisper and the conversation model now receive these bytes instead of averaged ones: their thresholds were measured on the old bytes and are to be re-measured live.
- Microphone (`watchMicrophone`, `microphoneWarning`, `onMicrophone` -> store `micIssue`, `restartMicrophone`): a Bluetooth hands-free (HFP) name or a track at 16 kHz or less is said once at start; `ended`, and a `mute` lasting `MIC_MUTE_REPORT_MS` (1500), are shown with "Restart the microphone" (stop + start); `unmute` clears a mute notice.
- Ducking is `DuckController` behind `setPolicyHold(held, immediate)`: attack 40 ms, hold at least 350 ms, release only 850 ms after the last request to duck (longer than the 750 ms probe cadence, so it does not pump), release ramp 250 ms, and a 12 s cap so it can never stick. A decision that already ended (admission, a new reply) passes `immediate`.
- Speech over the assistant's playback: once the echo guard confirms the user's own voice, the store ducks at once and `SpeechBoundary.quicken()` probes
  immediately, then every 0.5 s (`reset()` restores 0.75 s). Probes and finals carry `voiced_s`; `overlap: true` and, at the onset, `heard
  {phrase_id, played_s}` only when true. `continue` lifts the duck 400 ms after the user's speech ends (`releaseAfterSpeech`), `listen` for a finished utterance turns nothing down and keeps it open (its later admission applies); for speech still going on `listen` keeps it
  and renews the hold, `candidate.admitted.fade_ms` fades the old audio on its own gain before it stops (at most 1 s), `ignore` + `reason` is noted.
- Playback can't go silent unnoticed: `devicechange` follows the chosen output, else the default (`setSinkId('')`; a browser that cannot choose is
  never suspended and resumed to "reopen" it, only its state is reported), a paused context is resumed on
  visibility, focus or the next key/pointer press and reported ("Audio paused — click to resume"), a phrase not started 4 s after it was due is
  released as interrupted, buffered audio may run 90 s ahead (4096 sources), one failed phrase is ignored to its end, and every failure says
  Convo keeps listening. "Play test sound" uses the same output path.
- History shows one entry per turn (`foldTurns`): the user's words (a Whisper transcript, else what the model heard), the assistant's delivered
  text (phrases are spoken trimmed: joined as the server's history joins them, one space between two that do not already meet at a
  space, so a reply heard in full is never called interrupted) labelled with the `history` response's `assistant_name` ("Convo" when
  absent), "· interrupted" when cut; the live draft shows `draftText` (the reply so far without Markdown, `plain-text.js`, the
  browser copy of the server's `convo_plaintext`); developer view adds detail and
  not-answered notes. Bookkeeping rows (`HIDDEN_KINDS`) need developer mode AND `show_diagnostic_events`; generated-but-undelivered text (the
  "generated, not delivered" entry and the "not heard" remainder) needs developer mode AND `show_rejected_responses` (the store passes both
  flags; called without them `foldTurns` follows `developer`). A user turn without words is no row (its reply still is); developers see a
  faint row (`faint`, `data-faint`) whose detail is "No words captured" and the reason when known (held, interrupted before the words were
  known). A part without words that a later turn's audio holds is no row even there; that turn says "said in N parts". Outside developer
  mode "Reply interrupted" is a row only when some of that reply was delivered. `turn.superseded` {by} (a `HIDDEN_KINDS` row): outside developer mode the taken-over row is hidden once any turn that
  took it over, followed along the chain, carries words (their audio is joined); while none does, its own words stay shown. `turn.held` {decision silent|wait, reason} keeps the user's words; developers see
  "· stayed silent: <reason>" / "· waiting for you to finish". A live `notice` `kind: held` is a developer-only note, never a toast. The status
  chip mirrors the orb (Hearing you, Thinking, Speaking, Muted, Waiting for a model or a server, activity such as "Searching the web…").
- Errors go away (`convo-store.js` `fail`, `clearError`): an error is shown and logged with a kind. 'turn' clears when a later turn's words or
  sound arrive or its phrase plays (later = first met later by this page, `orderOf`; what is left of an earlier reply proves nothing),
  'playback' when a phrase plays (`playbackRecovered`), 'page' when the same `source` works later (`settled`: status, history, camera,
  screen, settings, work, job, dictation, action); any of them after `errorShowMs` (12 s). 'ended' (refused start, lost connection, failed
  chat switch or status) keeps its words until Dismiss or the next start, but the chip and orb stop being red after that time
  (`errorQuiet`; the orb gets the error only while it is loud, and the line is an `alert` only then), and it comes back quietly after a
  newer error cleared. A new `fail` call states its kind; a `stale`/`busy` playback acknowledgement is not an error. Every error (and an
  ended microphone, a missing transcript, a tune refusal, a Settings failure through `noteProblem`) goes to `problems`: memory only, last 50,
  consecutive identical ones merged with a count, shown in the diagnostics panel as "Recent problems" with Clear. Tests: `error-line.test.mjs`.
- Waiting (`waiting` = `loading` || `unavailable`): `notice` kind `loading` as before; kind `unavailable` (a server Convo needs does not
  answer) is the same chip state, orb state and note line in other words, never an error, and stays through states and errors. `ready`,
  a reply's words or sound, or stop clears both. `notice_retry` {job_id} takes the job out of `noticeSeen` so the next quiet moment offers
  it again (the server bounds how often); a job is marked seen before the request, so a retry that follows at once is not lost.
- Mute (`setMuted`, `pushToTalk`, `micMuted` = muted and not held open; the panel's Mute button, only during a conversation): `AudioSession.setMuted`
  disables the microphone track and disconnects the source from the capture, so the worklet and the echo guard are fed nothing (silence
  during playback would read as a room without echo and the assistant's own voice would pass after unmuting); blocks on their way are
  ignored. Playback, notices and the session go on. Unmuting resets the boundary, pre-roll, gate and voicing, and the guard (`echo_reset`)
  with its learned path given back (`echo_restore`), as a recreated session has it. Muting drops the open utterance (`dropUtterance`): no
  probe or final of it is sent, its candidate stays known so an admission on its way still moves the epoch, `convo.candidate_cancel
  {turn_id}` tells the server when a probe had been sent, and until the server answers `cancelled` the next utterance carries on under its
  id and sequence (`resumeAbandoned`) instead of being answered busy. Letting go of push-to-talk completes the utterance as a turn
  (`SpeechBoundary.finish`). A completed turn waiting for its decision is kept. Survives a chat switch (the new session is created
  `muted`) and a re-attach; cleared on stop. The chip and orb read "Muted" above the other live states (`over`: speaking, thinking); the
  orb's muted glyph is struck through and nothing about it moves. Tests: `mute.test.mjs`.
- Hotkeys (`hotkeys.js` pure parts and `bindHotkeys`, `store.hotkey(action)`, `hotkeys-setup.js` + `hotkeys-field.html`): the setting
  `hotkeys` holds one combination or '' per action (`ACTIONS`), `KeyboardEvent.code` based, modifiers in one order; a key that types needs
  Ctrl, Alt or Meta, AltGr is never one, reserved and duplicate combinations are refused in the card and by `convo_contract`
  (`tests/fixtures/hotkey_cases.json` holds both tables together). The older `hotkey` stays a second way to start and stop, compared by
  character as before, with its own row. One document listener, only while Convo is on: no auto-repeat, not in a password or masked field,
  not while a combination is recorded (`recording.active`), and the press is taken from the page only when the action did something.
  Push-to-talk ends on the release of any part of it, blur or a hidden page. The card records with window-level capture listeners that
  stop every key (Escape cancels, Backspace/Delete turn off, Tab leaves), writes the shared draft, and says that hotkeys work only while
  the Agent Zero page is focused. Tests: `hotkeys.test.mjs`.
- The panel has no Dictate button: dictation is the held orb, the host's microphone button or the dictation hotkey (`toggleDictation`); the
  chip and the note line say so while it runs, and the orb, the hotkey or Escape (which discards) ends it.
- The voice row (`synthesis-controls.html`, `synthesis-setup.js`; the sound drawer and diagnostics Tune) shows only for the user's own audio.cpp
  server. Opening it calls `synthesis_read`, then `synthesis_resolve` once per listed profile (read-only) to pre-fill each field with the
  profile's own value; a dot (with hidden words) marks an override; "Reset to profile" clears overrides. The profiles are a segmented choice
  showing each start-up buffer by the fork's rule (`primeMsFor`: low-latency 800, balanced 1280, quality 1760 ms after id normalisation, else
  first_block_frames x 80 ms, at most 2000) and, for the active one, the last measured first audio (`timingReport` speech_end_to_audible_ms) or
  "not measured yet". The row edits its own choice (`ui.synthesis.work`, started from the saved default in `baseline`), never the Settings
  draft, so a click or edit never dirties Settings. A click applies at once, an edit after 400 ms, through one apply loop (`synthesisRun`):
  the newest queued choice is always applied next (never dropped); a `pending` answer or a starting conversation shows "Applies when the
  conversation is ready." and retries every `RETRY_MS` for up to `RETRY_LIMIT_MS`; a refusal shows at once and the conversation keeps its
  previous voice. `synthesisStatus()` shows "This conversation: …" (its own choice, or the saved default after a stop/start) and "Saved
  default: …" separately, plus the server's last refresh error. "Save as default" first resolves the choice with the server and checks it
  against the preset (`fitProblem`), then patches `roles.tts.tuning` only; switching presets drops block-size overrides that no longer fit
  (`fitting`). Look-ahead and flush are not shown (stored only); the four sampler fields show only with native PCM (without it the server
  pins Quality's sampler). A table shows the voice model's own defaults (`MODEL_DEFAULTS`) beside each preset's values.
  `max_reference_seconds` is whole seconds 1-30. Nothing is created or selected on the server.
- Voicing (`voicing.js`, pure): per 20 ms frame at 16 kHz, RMS, normalized autocorrelation over 70-400 Hz after the main lobe, an adaptive dB
  floor (fast fall, 1 s rise) and a steady-tone rule (pitch and level held 160 ms = a machine, not a voice; the floor jumps to it). Voiced =
  level >= noise gate AND >= floor + 9 dB AND periodicity >= .5; onset needs 3 such frames averaging .7 and not decaying 9 dB, then 120 ms
  hangover. The guard runs it in the worklet; echo protection Off runs it on the page beside the untouched `audio-worklet.js`
  (`UnguardedCapture`). Tests: `voicing.test.mjs`, `echo-guard.test.mjs`; rig `../../../../convo-live-test/guard_replay.mjs` replays the
  corpus. Synthetic and recorded clips only; a real room is a listening test.
- Noise gate and end of turn (`NoiseGate`, settings `noise_gate_db` -66 = off..-3, default -50; `end_of_turn_seconds` .5-2, default .9): the gate
  (5 ms attack, 250 ms hold, 80 ms release) multiplies what is counted and sent, after the guard's analysis (which always sees raw mic +
  reference); voicing needs its threshold too. `SpeechBoundary.push(chunk, floor, verdict)` counts only voiced blocks toward `minVoiced`, the
  speech total and `voiced_s`; the silence that ends a turn is `endSilence`. `AudioSession.setSound` changes both live (worklet message
  `{kind:'sound', gateDb}`).
- Meter: every capture message gives the raw microphone level (before guard and gate) to `onLevel('input')` and `onMeter({level, withheld,
  voiced, state, playback})`; the store keeps `meter` (at most every 66 ms) and `meterTap` for Measure room. Visuals never gate capture.
- Sound drawer (`sound-panel.html`, `sound-setup.js`, store `convoSound`; the panel's "Sound" button and Settings -> Voice & Audio): the gate
  handle and the meter share one dB axis (-66..-3, leftmost off), "withheld as echo" is its own tick and words, Measure room (3 s, floor + 8
  dB, only with a live session and never while the assistant plays or in its echo tail: the meter reading carries `playback`, a reading during
  playback ends the measurement with `MEASURE_PLAYING`), Interrupt after (.4-2), End of turn (.5-2), Echo protection; developer mode shows guard state and voicing.
  Values are per device in `localStorage` `convo.sound.v1:<inputDeviceId>|<outputDeviceId>[#media|#call]` (input = the live track's deviceId
  once a conversation runs, else the host's selected microphone; output = the device chosen for that microphone, else the context's sink;
  the phone audio mode suffix only on phones, so each mode keeps its own calibration; the old `default|default` values are copied once to the
  first real key a conversation reads (`migrateLegacy`, marker `convo.sound.v1.migrated`, original kept for rollback; until then a key with
  none of its own reads them, `soundSource`); only changed keys; every storage call wrapped;
  blocked storage = page-only, said so); saved settings are only the defaults ("Use as default" = `setup_patch`). Changes apply live
  (`convo.applySound`); echo protection to or from Off waits for the next start. Overlap probes (not finals) carry `barge_in_s`.
  Tests: `sound.test.mjs`, `store-sound.test.mjs`.
- Start-up buffer: `audio.begin.prime_ms` (0-2000, the server applies the fork's rule): a PCM phrase that begins with nothing playing or
  scheduled holds its chunks until that much audio arrived (or `audio.end`), then schedules them back to back; phrases queued behind playing
  audio and absent/0 start as before.
- Build check: the first `status.build` the page sees is remembered; a different later one shows the non-blocking "Convo was updated — Reload to
  use the new version" banner with a Reload button (never an automatic reload).
- `SpeechBoundary` cuts a turn on the exact sample of the server's maximum length and
  carries the rest of that block into the next utterance, so an uploaded turn never
  exceeds what the server accepts.
- The speech gate constants (`policy_gate.*`) are plain probability inputs in Advanced ("Speech gate"). They belong to one decision model and one kind of speech: the hint says so, tells the user where to measure again (`tests/calibrate_gate.py`), and says that work with side effects always needs an explicit request at 0.9 or more. The server refuses an inconsistent set (ambient below active, a waving-away floor under 0.5) and the editor shows its message. Whether the gate is calibrated or unsupported for the selected classifier is a readiness row (`speech_gate`), not something the browser infers.
- "Answer length" and "Spoken task updates" (Conversation section) are plain enum selects on the shared `convoSetup` draft (`response_detail`, `spoken_updates`), so the plugin Config and the canvas gear modal edit the same value; `tests/test_settings_coverage.py` keeps every stored setting bound to a control. The hint states the boundaries (next response versus session start) and that errors, permissions and decisions are always spoken. Nothing in the interface may imply streaming input.
- Use host theme tokens and button conventions. The sidebar explicitly owns its column layout; do not rely on inherited panel flex direction.
- Delayed transcripts replace the matching visible accepted-turn text without mutating the durable event journal. Generated drafts and playback-start events are not delivered speech.
- The page never asks Whisper when a turn is admitted. The server writes a replied-to turn down itself after the reply was heard (`transcript.saved` refreshes the history, whatever the epoch), or, only while its worker cannot run, sends `transcript.wanted` with the turn's audio: the page then asks Agent Zero's `/transcribe` through `hostTranscribe` (one request at a time, a later turn is skipped; Convo stops waiting after `WHISPER_ABORT_MS` 15 s, yet the request counts until the host answers) and posts `convo.transcript` with the turn's own epoch (`turn_epoch` of the event; a barge-in since then moved the session on); a failure is a note and a toast, never the error state. A text-only conversation model's turn asks the server first (`convo.whisper`, 25 s request timeout) and uses `hostTranscribe` only on `by: 'browser'`.
- The canvas panel is history-first: a compact header (status chip, Voice Studio, settings gear), the chat target, the conversation controls, then the transcript, which is the only scroller. Settings never render in the panel; the gear opens `settings-modal.html` through `ensureModalOpen` over the same `convoSetup` draft the plugin Config uses, and closing a dirty modal asks first. The "jump to latest" button stays outside the scroller (inside it, showing the button lengthens the content and un-pins the reader). A card that opens, closes or grows above it never un-pins them either: its size is watched (`watchSize`), and a scroll event counts as the reader's only when it moved up in a layout that is still the one last looked at (events come a frame late). Journal bookkeeping (`assistant.generated`, playback starts, compaction, job lifecycle noise) is hidden outside developer mode; only real journal facts are described, never inferred markers.
- The host moves a modal's `[data-modal-footer]` out of the body: bind `:hidden`, not `x-show`, inside it. The host provides no focus trap; the modal wraps Tab itself. Use timers, not `requestAnimationFrame`, for settle logic (frames pause in a hidden pane).
- The composer orb is Convo's visual state layered on the host microphone button (`orb.js` + `page-head/zz-convo-orb.html`) and is released exactly when Convo is off. State comes from `orbView`; every state has its own glyph, a spoken label and `aria-pressed` truth, so nothing relies on colour; hover only brightens. The host rewrites the label and pressed state on its own events, so the orb watches and reasserts them. One capture and one set of existing meters feed it; the orb adds no stream, model or admission change.
- The orb's press gesture is `dictation.js`: a pure state machine (`createGesture`, injected timers, no DOM) plus a thin DOM adapter (`bindOrbGesture`). It only decides (`PRE_OPEN_MS` opens the silent buffer, `LATCH_MS` adopts it as latched dictation, `PUSH_TO_TALK_MS` makes it push-to-talk; `data-convo-capture` is the quiet mark while it buffers); the store acts on its effects (`tap`, `arm`, `push-to-talk`, `latch`, `finish`, `cancel`, `abort`). The click that follows a handled release is swallowed (`consumeClick`), a click with no press (assistive technology) acts as a tap, and Space/Enter on the focused orb are the same gesture.
