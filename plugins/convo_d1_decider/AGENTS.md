# convo_d1_decider

Development-only provisioner. It registers a served `d1-omni`-style decision model as the System One decision backend `d1_llama_cpp` for **Convo only**, until System One ships its own provisioner. On the user's instruction (2026-10-17) it is extended rather than only replaced: it serves both decision choices of Convo's Classifier card (the toggle "Use System One's decider", and Convo's own classifier when it is a decision model). Retire it once System One provisions an audio-capable decider itself.

## Contract

- Touches no Agent Zero chat, tool, prompt or model call: the only extension is an `agent_init` hook that calls the idempotent `ensure_registered()` (the registry lives in the host process and starts empty); it swallows its own errors so an agent never fails to start because of it.
- The gate it hands System One's consumer client admits the `convo` consumer only, and only while this plugin's own toggle is not disabled. Disabling the plugin (or Convo) leaves nothing registered (`hooks.py` unregisters).
- The decision server answers `POST /v1/systemone` (text and audio; images refused). Its address is resolved for **every call** (`resolve_endpoint`), from Convo's `decider.source`, read through Convo's own settings accessor (`convo_service.settings()`, keeping only `decider`, the derived root and the classifier's consent): `convo` = Convo's own decision classifier, the server root `convo_classifier_catalog.decision_root` derives from `roles.classifier` (provider and API base; a path prefix allowed) or, without a provider, `decider.url` (empty = `http://host.docker.internal:9931`); `system_one` = System One's decider endpoint only when its kind takes audio (`convo_system_one.inherited_decider(consent)`; its text-only kinds jev, openrouter, llama_decision and chat are refused, typed `text_only`); `''` = this plugin's `config.json` `{"base_url": ...}` or the default. With Convo off, Convo is never imported and `''` applies. The resolution is cached by the saved settings files' time and size (this plugin's, Convo's, System One's), so a changed address applies to the next call without registering again.
- Every source obeys the classifier's locality rule (`allowed_url`, the mirror of Convo's `convo_contract.classifier_url`; the tests hold both to one table): this machine, Convo's containers and your network (LAN and Tailscale, Convo's `local_host`, mirrored here and held to Convo's `tests/fixtures/connection-rules-cases.json`) as they are (http or https); a public address only with Convo's classifier consent (`roles.classifier.remote`) and over HTTPS; a valid port, no credentials, query or fragment, and no path except a root derived from an API base. With Convo off there is no consent, so this plugin's own address must be local. A public address without consent is refused (`remote`). A bad address never blocks registration: the call is refused before anything is sent (`DeciderUnavailable`, codes `text_only`, `remote`, `invalid_url`, `not_installed`, `not_configured`, `unknown`, `unavailable`), the SDK reports it as a decision failure and Convo's turn is degraded. Nothing falls back to another server. Nothing here starts, stops or loads the model.
- A call to Convo's own decision classifier (source `convo`) sends `Authorization: Bearer <key>` when Convo resolves a key (`convo_setup.classifier_bearer`, called in-process for each call: the classifier's environment reference, Agent Zero's key for its provider, or Convo's key bound to that server root). Calls for the other sources carry no key. The key is never cached, stored, logged or put in status.
- `helpers/core/decision.py` and `media_decision.py` are copies of System One's canonical SDK files (`C:/a0-plugins/portable/system_1/core`, hashes pinned in `helpers/provisioner.py`); a changed file is refused. Re-pin only from System One's source, never by editing the copy.
- Nothing is stored: no keys, no audio, no answers. Status shows counts, last latency, the last error class, and where the next call would go (`source`, `host`, `base_url`) or why it would be refused (`refused`, `refused_detail`); it never contacts the server.

## Operation

- Install or update with `plugins/_convo/tests/update-persistent.ps1 -Plugin convo_d1_decider -Target test|production [-Apply]` (production also needs `-ConfirmProduction agent-zero-v2.11` and the user's approval). Then enable the plugin natively and set the Classifier in Convo → Connections (a decision-model provider, or "Use System One's decider"; either selects System One → `d1_llama_cpp`).
- `POST /api/plugins/convo_d1_decider/provision` `{action: status|register|unregister}` for diagnostics.
- Tests: `python -m unittest plugins.convo_d1_decider.tests.test_provisioner` from the repository root (a stubbed host; Convo's real settings accessor reads temporary settings files).
- `api/provision.py` reloads `helpers/provisioner.py` when the file differs from what was loaded (`SOURCE_STAMP`; toggling a plugin does not reload its Python), removing the old registration first and re-making it with the new code, so a scoped update never leaves the previous code serving decisions.
